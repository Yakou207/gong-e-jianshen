# 任务
调查阶段已结束。只依据本对话中实际成功的工具返回，输出一个 JSON 对象，作为研判意见草稿交人工复核。不要输出 JSON 以外的内容。

# 输出结构
{
  "recommendation": "report_suspicious | exclude | insufficient_evidence",
  "summary": "两三句话：结论与最主要的依据",
  "risk_findings": [{"finding": "一条可疑特征", "severity": "high | medium | low", "evidence": [{"tool_call_id": "调用ID", "transaction_ids": ["该调用返回过的交易ID"]}]}],
  "mitigating_findings": [{"finding": "一条支持合理解释的事实", "severity": "low", "evidence": [{"tool_call_id": "调用ID", "transaction_ids": []}]}],
  "focus_answers": [{"focus_id": "预警关注点ID", "status": "explained | unexplained | needs_information", "answer": "该关注点的调查结论", "evidence": [{"tool_call_id": "调用ID", "transaction_ids": []}]}],
  "information_requests": ["需要补充的尽调材料或需向客户核实的问题"],
  "draft_opinion": "可供甄别人员直接修改的研判意见，不超过 300 字"
}

# 判定口径
- report_suspicious：存在与客户身份、经营背景明显不符的资金特征，且现有资料不能合理解释。
- exclude：每个预警关注点都已由材料和流水得到合理解释，且检查期间流水覆盖完整。
- insufficient_evidence：关键资料缺失、流水覆盖不完整，或解释成立需要补充尽调。

# 硬性要求
- 每条发现和每个关注点回答至少引用一个实际成功的 tool_call_id；transaction_ids 只能填该次调用返回过的交易。
- 文中出现的金额、笔数必须与工具返回一致；不确定就不写数字。
- 每个预警关注点必须有且只有一条 focus_answers。
- 没有查到的事项写进 information_requests，不要假定。

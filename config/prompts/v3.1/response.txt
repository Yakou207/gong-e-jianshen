# 任务
只判断处置理由是否对每个预警关注点（focus）作出了实质论述。addressed 只表示原文已回应，不表示核查已完成、结论正确、材料齐备或解释充分。只依据本请求中的原理由、focus、任务规范与检查范围，不猜测后查证据或人工答案。

# 输出
{"focuses":[{"focus_id":"输入ID","status":"addressed|not_addressed|pending_judgement","quote":"唯一连续理由原文；未回应可空","reason":"针对原理由的简短依据"}]}
- 每个 focus 恰好一条，禁止其他字段；quote 必须是 narrative 中唯一的连续跨度。下附 JSON 结构为实际契约。

# 判断步骤
1. 确定每个 focus 要求原文说明的独立事项：
   - 有 response_requirements 时，只逐项判断其中的作者回应义务；focus.text 只提供背景，不能从复核人员的核查动作中额外添加作者义务。
     - explanation：原文说明了所问对象、用途或关系；有具体可理解的关系陈述或具体未决说明即可，不要求报告核查已完成。
     - verification_result：原文明确报告了所问核对结果；指向材料或说明用途不能替代结果报告。
     - unresolved_item：原文回应了 text 给定的特定未决事项（现状或处理）；不能靠后查结果替作者回答。
     - 一个 focus 可有多个义务，须逐项回应。
   - 没有 response_requirements 时，按任务规范识别需要原文说明的对象、用途、去向、来源、关系或已知未决事项；把它们与复核人员的核查动作区分，不把后查才能确定的结论当作原文必须已有的内容。规范明确要求报告核对结果或列明特定未决事项时，也逐项检查。
2. 什么算实质论述：
   - 对所问事项作出可理解的具体说明，或说明该事项中哪一关系尚未确定及所需资料。
   - explanation 类或未要求报告结果的事项：原文陈述了所问关系并给出与该关系相关的具体核验线索，即可回应对同一关系的核验要求，不必另行展示核查过程。显式 verification_result 与 unresolved_item 按各自义务优先，核验线索不能替代。
   - 仅声称做过检查、笼统评价、泛指附件、承诺以后处理或复述问题，不算实质论述。材料引用只是核验线索，不能代替原文对事项本身的说明。不按某个词是否出现作判断。
3. 定性：每个独立事项都有实质论述 → addressed；有明确遗漏 → not_addressed 并指出遗漏事项；原文含义或规范要求确实无法确定 → pending_judgement。多个 focus 分别判断，不能互相替代。

# 注意
- reason 只描述原文实际说明或遗漏的内容。原文只说某文件未制作，不得改写成必须补该文件、已有关系缺口或关系不存在。
- 已有针对性解释但事实有误、证据不足或材料不对应，不改判为未回应；这些由独立的事实与支持核验处理。

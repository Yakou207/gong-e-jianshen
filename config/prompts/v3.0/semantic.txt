# 任务
仅依据本案来源和实际已读的工具结果，判断（一）理由中已陈述关系的支持缺口 gaps，（二）可选的新线索 leads。理由是否回应关注点由另一请求判断，本步骤不重判回应。

# 输出
{"gaps":[{"basis_kind":"identity_unresolved|missing_linked_material|material_mismatch|explanation_support","basis_ref":"本次目录允许的ID","quote":"唯一连续理由原文","requested_material":"具体尚缺信息或待核冲突","reason":"具体缺失或冲突"}],"leads":[]}
- 禁止额外的顶层或条目字段；引用字段只有 basis_ref（不得输出 basis_ref_id、focuses、status、title 等）。下附 JSON 结构为实际契约。
- 没有实际缺口则 gaps=[]；leads 最多 3 条。quote 只能来自 document_id=narrative，不能用预警、材料或流水冒充原理由。只写简短依据，不输出内部推理。

# 一、确定要核查的关系
1. 只核对原关注点范围内、原理由提出的实质关系；每项关系分别检查记录范围、关联依据与各端字段。
2. 关系支持检查独立于数值事实抽取和身份缺口：checks.claims、material_links、material_results 为空，或已有 identity_unresolved，都不能跳过。材料目录为空只表示没有材料，不表示原文没有关系命题。
3. 原文只说明核查动作已完成或将要核查、没有提出具体业务关系时，没有可检验的关系命题；不得为让作者补写解释而新造 explanation_support（论述缺失只在 focus 处理）。原文明确说影响其关系解释的资料缺少或待补时，才保留该具体缺口。
4. 已发生的对应关系，以及尚未发生安排所称的约定、到期条件或其他依据，都按原文实际声明核验；尚未发生不表示已引用的依据无需核验，但不要求未来的执行凭证。原文未声称具体依据的单纯意向，不补造关系。
5. 一般真伪、合成来源、经济合理性、人工最终确认是能力边界，本身不产生缺口。

# 二、怎样算有支持
1. 先确定被解释的记录集合，再对照材料声称的关系与实际流水。只有原文或冻结任务明确提出全集命题，才要求枚举该集合。
2. transaction_observations 来自实际成功查询，含范围、覆盖和实际字段；按 transaction_id 核对方向、对手、金额、币种、时间。材料字段是待核陈述，不能覆盖同 ID 的实际流水值。工具失败、未读记录或覆盖不足都不能当作证实。
3. 材料明确给出关系两端的交易标识等可核信息、且相关流水字段一致时，关系已获支持；不再要求换一种表格、同一关联的原始单据或额外实名证明。
4. 只有金额相等、同对手、时间先后或一般备注，而材料没有明确连接两端时，关联仍未支持。完整读取两个方向的流水也补不出缺失的业务关联依据。relationship_support_source_candidates 只是候选目录，须核其内容是否明确连接所述两端。
5. 金额核对分两类：同一交易 ID 的材料字段须与实际流水一致；原付款与退款等不同 ID 之间的金额关系只按原文明示或适用模板核验，不默认全额退款，也不默认两笔相等。退款少于原款不单独构成冲突；材料把某退款 ID 的金额写错时，要求补正该 ID 的差异，保留已一致的原付款字段。
6. 关系方向按 focus 和理由确定：解释各笔转出去向，就逐笔检查转出是否关联原对象；不反向要求每笔转入都有退款。与被解释关系无关的交易不成为必需补证。
7. 被解释侧与支持侧分别判断：支持端明确列出的记录与来源足以支持被解释记录时，不因支持端未枚举全集而追加补证；只有已见关系确实需要、或原文/任务明确提出该侧全集命题时，才继续核验支持侧其他记录。
8. 单笔有依据不证明其他记录也有依据。

# 三、范围、覆盖与读取进度（只描述证据边界，不是异常）
1. read_scope_progress 由实际成功查询计算：whole_visible_interval_read=false 表示该方向整段可见记录尚未枚举；按 ID 的逐笔查询不能证明整段已读。同时列出 in/out 只是读取计量，false 不能反推存在全集义务。
2. 已查询整个区间只说明当前可见记录已枚举；来源 coverage 仍可能是 partial 或 unknown。此时写“该区间资料覆盖不完整，其他记录是否存在尚不能确定”，不能写“未查询/未读取”。只有 read_scope_progress 显示相关范围未枚举，才提出补充范围查询。
3. coverage=partial 不表示区间内没有可见记录，也不表示已返回的记录未被读取；已返回记录仍是可见事实，已支持的逐笔关系保留，不重复索证。覆盖不足只补缺失区间和必要字段。
4. material_transaction_read_progress 只记录材料显式引用交易的读取进度：pending 表示未核查，不能按 ID 推断方向、金额或对手；read_returned 的字段仍按 transaction_observations 核验；queried_no_visible_row 只说明当前可见范围未返回，不证明不存在。
5. 未完成的必需核查保持必需状态，不降为可选线索；也不能从“可能还有未读记录”推导出新异常。

# 四、gap 的绑定规则（gap_basis_catalog 列出每类允许的 basis_ref；某类为空则不得输出该类）
1. identity_unresolved：basis_ref 为 checks.claim_results 中 execution_status=identity_unresolved 的 claim_id；quote 取该 Claim 的 text。它表示原文所指对象或交易范围尚未可靠定位，不一定是实名缺失；请求明确标识、范围对应依据或人工确认映射，不把角色词当真实名称，不自动要求实名。token 存在或材料列出交易 ID，不能单独证明原文引用与 token 或全部交易范围的映射；相同明确 token 的跨笔比较不需要额外实名证明。
2. missing_linked_material：basis_ref 为已有 MaterialLink 的 link_id，且其引用的材料在目录中缺失。
3. material_mismatch：basis_ref 只能是确定性 material_results 中 result=mismatch 的 link_id；材料 ID、交易 ID 都不是 link_id；corresponds 不能改判 mismatch。
4. explanation_support：basis_ref 固定为 narrative，只用于上述范围内的具体关系缺失、实际字段冲突、关联记录未读或覆盖不足，并说清是哪项关系、缺哪部分信息。没有预设 MaterialLink 但已见材料与流水冲突时也用这一类，不得伪称确定性 mismatch。
5. checks.claims 是当前生效命题；origin=human_reviewed 只表示结构经人工复核，不代表事实支持；不复用已被替代的机器命题。binding_status=needs_review 的材料关联须人工修订。
6. 去重：与已记录 identity_unresolved 的同一映射缺失合并；不重复已有的确定性次数/金额矛盾；不把同一缺口拆成多条。同一份缺失资料影响多项关系时可合并为一条，但 quote 须覆盖所涉原文，reason 与 requested_material 逐项说明各关系缺什么。已有支持和已确认字段保留，不重复补证。
7. requested_material 必须针对已确认的缺失关联、冲突字段或未核查范围，与被解释集合或实际需要的支持端点一致；不得附加原文与模板未要求的全额相等条件，不为已支持关系重新索取凭证。

# 五、可选线索 leads（完成 gaps 后再判断）
1. 每项为 {"observation":"未核实观察草稿","question":"可新增的具体核查问题","basis_refs":["lead_basis_catalog 或成功工具返回的 lead_basis_ref"]}。
2. 必须基于已读资料中具体值得核查的观察，且与原预警、已有 focus、事实矛盾、必需 gap 都不重叠；同一对象和待核关系已处理就不再重复。
3. 不能因另一笔正常交易不在本次关系材料里，就发明其应有的退款、合同或安排；只观察到入账且无返还义务或异常依据时，“是否也应退款”不是线索。partial 区间里有若干可见记录本身不构成线索。
4. 不确定是否新颖时返回 []。证据可定位只表示来源可查，观察和新增范围仍须人工确认，不能自动升级或断言洗钱。

# 任务
在最终语义判断之前，自主选择本案只读工具追加取证。原始理由、材料和确定性必需检查已经提供；先读已给内容，找出能由工具缩小的具体缺口，再查询。计划文字不能冒充工具结果。

# 预算
- 最多 3 轮，每轮最多 2 个工具调用；总模型调用上限 6（含抽取、回应判断和最终 JSON）。
- 每轮只实际执行前 2 个调用；多提的调用会收到“未执行”返回，不提供事实，不能声称已核实。需要更多信息时，用一次覆盖该期间的查询取多条流水，或留到下一轮。
- 预算耗尽保留未完成，不能视为已核实。

# 已提供的信息（initial_information）
- case.documents、case.materials：当前版本全文与字段；case.coverage：来源覆盖声明与缺失范围；case.checks：确定性核验摘要。
- 用 read_document、read_material、check_coverage 重读同版内容没有新信息，不要为凑轮次重读。
- 覆盖声明不等于已读取流水；实际流水字段和读取范围以成功的 query_transactions 返回为准。

# 选择查询
1. 每次调用前想清楚它补充哪项尚未见到的字段、范围、规则定义或可靠对象映射；只在能缩小具体待核事项时查询。不要求固定工具、顺序或最低调用数。
2. 先看 focus 与理由解释的是单笔还是整个期间某方向的记录。若是全部记录且该方向 whole_visible_interval_read=false，已有 ID 对应不能替代完整范围读取，应在剩余轮次内读取该期间方向；无剩余轮次时在最后说明范围未核查。
3. 材料给出交易 ID 时，可用 query_transactions 的 transaction_id 直接定位；核对材料所称对手/方向时不要把待核字段同时作为过滤条件，以免漏掉同 ID 不同字段的冲突。单笔过滤返回空集不代表全案没有记录。
4. 查询用的 ID 必须来自已见资料，时间窗来自本案或实际返回；前一查询返回才知道的标识或时间，须收到结果后再构造后续查询。
5. read_material 的 ID 只能来自材料目录或 material_links 的明确引用（initial_information.known_material_ids）；被引用但缺失的材料可以读取并得到“缺失”返回。不得猜测文件名或材料 ID。
6. resolve_entity 查原文名称时传原文名称；查 token 只证明 token 存在。
7. material_transaction_read_progress 中 pending 的交易未读取，不提供方向、金额、对手；应在剩余轮次内用 query_transactions 读取，不预设方向或对手过滤。

# 结束
- 有剩余轮次且工具还能提供必需范围或字段时，继续自主查询，不要把可执行的本案查询改成请求人工提供。
- 已有返回足够、工具确实无法缩小待核事项或预算已尽时，用简短文字说明结束原因，由独立最终步骤给出 JSON。本阶段不输出最终支持 JSON 或缺口候选。
- 只用已读证据。成功工具的 lead_basis_ref 可作新观察来源；失败、缺失或身份未解不能伪称核实。必需缺口不能降为可选线索；范围未读、覆盖不足只是证据边界，不是新异常。
- 关系两端需要实际字段及明确关联依据；同额同对手、时间或备注不自证经济关系。工具无法提供的依据，在最终候选中写明涉及哪些关系、缺哪些依据，不以一项缺口概括后漏掉其他关系。
